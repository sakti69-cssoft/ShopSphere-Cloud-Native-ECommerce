# ShopSphere security review

## Phase 8 scope and verification

Review date: 2026-09-07. The existing production host uses encrypted EBS,
IMDSv2, SSM administration and public TCP 80/443. Production environment files,
TLS keys, Terraform plans/state and backup contents stay outside Git.

These repository changes address findings from actual CI image scan logs:

| Severity | Finding | Change | Verification boundary |
|---|---|---|---|
| Critical | Embedded Tomcat security-constraint vulnerabilities in 10.1.55 | Pin the five servlet services to published Tomcat 10.1.59 | All five service test suites passed; CI image scan required |
| High | OpenSSL and Alpine packages behind available security fixes | Upgrade runtime Alpine packages during image build; pull base images | Patched Nginx image scan passed with zero fixable high/critical findings |
| Critical/high | Unneeded npm dependency tree in frontend runtime | Remove global npm from standalone runtime | Image scan/build required; Node executes server.js directly |
| High | Privileged cAdvisor and host Docker socket mount | Replace with constrained host timer and read-only Node Exporter textfile metrics | Collector unit tests passed; production verification required |
| Medium | CI shell syntax command only checked its first script | Iterate over every shell script | Repository CI gate |

The image gate remains enabled. Findings are not globally suppressed to obtain
a green build. Scan dates and immutable image revision matter: a prior passing
scan is not a permanent assurance.

## Controls

- GitHub Actions uses read-only repository permissions by default, with package
  write limited to image publishing and OIDC limited to approved deployment.
- Trivy scans secrets, IaC/configuration and runtime images. The local hygiene
  script rejects tracked production secret/key/state patterns. These are
  complementary checks, not proof that every possible secret is absent.
- CI runs Java tests, frontend lint/type checks/build, Compose validation and
  Terraform validation. SBOMs are generated by the image publication workflow.
- Runtime services use non-root users where practical, dropped capabilities,
  healthchecks and memory limits. Databases retain their official image startup
  behavior; no database ports are published by production Compose.
- Nginx terminates TLS 1.2/1.3, preserves security headers, and redirects normal
  HTTP requests while retaining the ACME challenge route.
- SSM instance role uses AmazonSSMManagedInstanceCore. GitHub deployment OIDC
  role setup is a separate uncompleted step; static AWS keys are not added.

## Remaining limits and review items

- Single EC2 host: no high availability, WAF, managed databases or off-host
  disaster recovery. Those services have not been created.
- Backup archives live on the same encrypted EBS volume; losing it loses both
  live data and local backups. Encrypted S3 with reviewed IAM/lifecycle is the
  recommended next storage tier, subject to cost approval.
- The root telemetry timer can query Docker on the host. Protect its code and
  systemd units as root-owned. It does not publish an HTTP Docker API.
- Node Exporter has a read-only host filesystem view for host metrics; host
  permissions and the runtime-directory mask limit access, but this remains
  sensitive host telemetry.
- Version tags and package repositories can change. Deploy immutable commit
  image tags only after scanning; record actual image digests for operations.
- The existing Trivy exceptions cover public HTTP/HTTPS ingress and absent VPC
  flow logs for this portfolio. They do not approve public SSH or database access.
- No external alert receiver, automated penetration test, compliance assessment,
  or successful OIDC production workflow is claimed.
